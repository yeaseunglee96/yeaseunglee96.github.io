지연은 물량이 아니라 '누가 무엇을 모르는가'에서 생겼다

  1. 증상

    긴급 건마다 메일이 오가며 대응이 늦어지고, 트럭이 창고 앞에서 대기하며 추가 비용이 생길 위험이 있었습니다.

  2. 원인 추적

    과장님이 주고받은 최근 3개월 치 메일을 유형별로 나눴습니다.
    창고 정보나 화물 상태를 뒤늦게 묻는 메일이 전체의 30%를 넘었습니다.

  3. 검토한 방법

    다른 부서의 업무 절차를 참고해, 자주 묻는 정보를 미리 정리해 둘 수 있는지 확인했습니다.

  4. 해결

    창고 정보 매뉴얼과 아침 현황표로 상대가 묻기 전에 알 수 있게 했습니다. 예정 시간에 맞춰 출하해 트럭 대기 비용도 막았습니다.

라스트마일 지연도 정보의 빈틈에서 생깁니다. 협력사·라이더·유관 조직이 묻기 전에 알 수 있는 흐름을 만들고, 반복 공유 업무는 AI로 자동화하겠습니다.

  1. 증상

    WASD 키를 계속 누르고 있어도 로봇이 잠깐 움직이다 0.4초 뒤에 멈췄습니다.

  2. 첫 판단

    화면 쪽 키 입력이나 연결이 끊기는 문제로 보였습니다.

  3. 진짜 원인

    화면은 키를 누르는 순간에만 명령을 한 번 보냈습니다. 로봇의 안전장치는 0.4초 안에 새 명령이 없으면 로봇을 세우도록 되어 있었습니다.

  4. 해결

    로봇의 안전장치는 그대로 두고, 키를 누르는 동안 명령을 1초에 10번(10Hz) 다시 보내도록 바꿨습니다. 창 포커스나 연결이 끊기면 전송이 멈춰 로봇은 안전하게 섭니다.

  5. 비슷한 사례

    화면 검사 도구가 바뀐 사양을 안전 결함으로 잘못 보고한 일이 있었습니다. 사양 원문과 대조해 검사가 낡았다는 것을 확인하고, 기준은 낮추지 않은 채 검사를 바로잡아 실패 18건을 0건으로 만들었습니다.

조리로봇 학습데이터를 만들기 위해 요리 영상을 AI(Gemini)가 투입·볶기·끓이기 같은 조리 단계로 자동으로 나누는 기업 연계 프로젝트입니다. 저는 AI가 읽을 사진 수를 줄여 비용을 낮추는 실험을 맡아, 시뮬레이션이 낸 절감안을 실제 AI로 두 차례 검증하고 원인까지 분석했습니다.

담당

사용 도구

  • 시뮬레이션을 그대로 믿지 않기사진을 22% 덜 읽어도 된다는 시뮬레이션 결과를, 토큰 상한을 승인받은 뒤 실제 Gemini로 영상 16편을 판독해 사람이 검수한 정답 286개와 비교했습니다.
  • 1차: 손해를 확인하고 철회토큰은 22% 줄었지만 정확도(F1)가 0.709에서 0.683으로 떨어져 제 제안을 철회했습니다.
  • 원인 분석놓친 경계 24개를 하나씩 분류해 54%가 사진 간격이 넓어 아예 보지 못한 구간, 38%가 AI 판독 오류임을 찾았습니다.
  • 2차: 같은 날 나란히 재실측원인을 피한 개선안과 기존 방식을 같은 날 같은 설정으로 실행(호출 617회)했지만, 짧은 단계 손실이 남아 이 안도 기각을 제안했습니다.
  • 데이터를 모을 앱 (개발 중)AI 학습 데이터를 모으는 요리 기록 앱을 React Native로 개발하고 있습니다. 대용량 영상 업로드와 사용자가 고친 단계를 검수 후보로 내보내는 기능을 만들었습니다.

좋아 보이는 절감안을 두 번 실측하고, 두 번 멈췄다

  1. 첫 판단

    시뮬레이션에서 AI가 읽는 사진을 22% 줄여도 정답 경계를 거의 그대로 찾았습니다. 하지만 AI가 사진을 완벽하게 읽는다는 가정이었습니다.

  2. 1차 실측

    실제 Gemini로 영상 16편을 판독해 정답 286개와 비교하고, 차이가 우연인지 영상 단위 신뢰구간으로 확인했습니다. F1이 0.709에서 0.683으로 떨어져 제안을 철회했습니다.

  3. 원인 분석

    놓친 경계를 분류하니 절반 이상이 사진 간격이 넓어져 아예 보지 못한 구간이었습니다.

  4. 2차 실측

    간격은 그대로 두고 후보 주변만 줄인 개선안을, 기존 방식과 같은 날 나란히 실행했습니다. 토큰은 16% 줄었지만 짧은 단계 재현율이 0.851에서 0.770으로 떨어졌습니다.

  5. 결정

    시뮬레이션이 두 번 모두 실제 손실을 작게 예측했다는 점을 근거로, 실측 없이 판독 기준을 바꾸지 않는다는 원칙을 보고서로 남겼습니다(팀 결정 전 제안).

현장에 적용하면
